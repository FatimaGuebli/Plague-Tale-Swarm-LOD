# Plague-Tale-Swarm-LOD

## Dynamic LOD Swarm Optimizer

This project is a small machine learning prototype for game optimization. It simulates how a game engine could assign Level of Detail (LOD) tiers to a dense rat swarm using gameplay telemetry such as distance, visibility, occlusion, and lighting.

The idea is simple: instead of rendering every rat at the same quality level, we classify each rat into one of three LOD groups so the renderer can spend more detail only where it matters.

## Project Objective

The main objective of this repository is to demonstrate a data-driven approach to swarm rendering optimization.

The project does this in three steps:

1. Generate a synthetic telemetry dataset for 5,000 rats.
2. Cluster those rats into LOD groups using K-Means.
3. Estimate the rendering savings gained by using lower-detail models for less important rats.

This makes the project useful as both a student report and a practical engineering prototype.

## Core Idea

Each rat is described by four features:

- `distance_to_player`
- `in_view_frustum`
- `occlusion_factor`
- `light_intensity`

These features are scaled to the `0-1` range and then passed to K-Means clustering with manually chosen centroids that represent desired rendering behavior.

The three target LOD classes are:

| LOD Class | Meaning |
|---|---|
| `LOD_0_HERO` | Close, visible, clear, and bright rats that should receive the highest quality. |
| `LOD_1_SWARM` | Medium-priority rats that still contribute to the scene but can use reduced detail. |
| `LOD_2_CULL` | Distant, hidden, or dark rats that can be aggressively simplified or culled. |

## Dataset

This repository currently uses **one saved dataset**:

### `rat_swarm_telemetry.csv`

This is the base synthetic telemetry dataset generated by `DataSetGenerator.py`.  
It contains **5,000 rows**, with each row representing one rat entity.

### Dataset Columns

| Column | Type | Description |
|---|---|---|
| `distance_to_player` | float | Distance from the rat to the player, in the range `0-100`. |
| `in_view_frustum` | int | Visibility flag: `1` means in camera view, `0` means outside view. |
| `occlusion_factor` | float | Visibility obstruction level from `0` to `1`. |
| `light_intensity` | float | Lighting intensity from `0` to `1`. |


## Clustering Strategy

The project uses `MinMaxScaler` and `KMeans` from `scikit-learn`.

Instead of random initialization, the clustering uses manual centroids designed around rendering logic:

| Cluster | Initial Centroid | Interpretation |
|---|---|---|
| `LOD_0_HERO` | `[0.0, 1.0, 0.0, 1.0]` | Close, in-view, not occluded, bright |
| `LOD_1_SWARM` | `[0.5, 1.0, 0.5, 0.5]` | Mid-range, in-view, partly occluded, dim |
| `LOD_2_CULL` | `[1.0, 0.0, 1.0, 0.0]` | Far, out-of-view, occluded, dark |

This gives the optimizer a more intentional starting point than standard random K-Means initialization.

## Optimization Logic

To simulate rendering cost, the project assigns an estimated polygon budget to each class:

| LOD Class | Polygon Budget per Rat |
|---|---|
| `LOD_0_HERO` | `5,000` |
| `LOD_1_SWARM` | `1,000` |
| `LOD_2_CULL` | `50` |

The optimizer then compares:

- a baseline where all 5,000 rats are rendered at `LOD_0_HERO`
- an optimized case where rats are distributed across the three LOD classes

This produces a simple polygon reduction report that demonstrates the value of dynamic LOD assignment.

## Validation

The project validates the clustering in two ways:

### 1. Visual Validation

`DynamicLODSwarmOptimizer.py` displays a 3D scatter plot using:

- X-axis: `distance_to_player`
- Y-axis: `light_intensity`
- Z-axis: `occlusion_factor`

Each point is colored by its assigned LOD group.

### 2. Mathematical Validation

The script also computes the **Silhouette Score** to estimate how well the clusters are separated.

This helps confirm that the LOD groups are not purely arbitrary and that the feature space has some meaningful structure.

## How To Run

Run the scripts from the project root:

```powershell
python DataSetGenerator.py
python KMeansLODClustering.py
python DynamicLODSwarmOptimizer.py
```

## Dependencies

Install the required Python libraries with:

```powershell
python -m pip install pandas numpy scikit-learn matplotlib
```

Required libraries:

- `numpy`
- `pandas`
- `scikit-learn`
- `matplotlib`

## Expected Runtime Behavior

When `DynamicLODSwarmOptimizer.py` runs, it:

1. loads `rat_swarm_telemetry.csv`
2. scales the telemetry features
3. clusters the rats into LOD groups
4. prints a cluster summary
5. prints the silhouette score
6. prints the polygon savings report
7. displays the 3D validation plot when an interactive matplotlib backend is available

No additional CSV or image files are saved by the optimizer.

## Engineering Summary

This project demonstrates how unsupervised learning can support real-time rendering decisions in a swarm-heavy game scenario.

From an engineering perspective, it combines:

- synthetic data generation
- feature scaling
- unsupervised clustering
- visualization
- optimization reporting

From a student perspective, it is a good example of how machine learning concepts can be applied to graphics and performance problems in game development.
